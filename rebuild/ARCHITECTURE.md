# 재구현 설계 및 구현 상태

이 문서는 목표 구조이며 현재 완료된 기능의 목록이 아니다. 구현된 내용은 README를 따른다.

```text
CLI / MCP / 선택적 로컬 IPC
             ↓
  애플리케이션 유스케이스
             ↓
      도메인 규칙
             ↑
SQLite · 프로필 파일 · 브라우저 감독 · 외부 금고 어댑터
```

도메인은 SQLite와 브라우저에 의존하지 않는다. SQLite는 WAL과 짧은 트랜잭션을 사용하고 세션별 실행 generation을 조건으로 상태를 갱신한다. DB 예약은 브라우저 소유를 증명하지 않으므로 실제 실행 전 별도의 OS 잠금과 감독 프로세스, 중단 후 복구 정책이 필요하다. 서버는 선택적이며 같은 코어와 잠금을 사용해야 한다.

금고가 비밀번호를 소유하고 KeyHarbor가 모델에 비밀을 반환하지 않는 경로를 우선 검증한다. 계정 참조나 사이트 이름도 민감한 메타데이터다. 브라우저 프로필 암호화는 KeyHarbor DB와 별개이며 OS 디스크 보호와 브라우저의 실제 동작을 검증해야 한다.

인증 인계는 요청 ID와 실행 generation을 연결하고 사용자의 재개와 로그인 성공을 구별한다. 직접 CDP 접근을 부여한 클라이언트가 있는 브라우저에서 인증 내용을 비공개로 보장하지 않는다. 기존 실험에서 CDP 연결 차단 이후에도 페이지에 예약된 JavaScript가 실행됐다.

완료 전에 실제 브라우저의 격리·재실행·감독자 중단, 동시 프로세스 충돌, 금고 대상 지정·비밀 노출, MCP 클라이언트와 사용자 인계, 서버/CLI 소유권 경쟁, 백업·복구와 보안 경계의 실패 경로를 검증한다.
