# 그림 먼저

문서, 계획, ADR, PR 본문, 대화 응답에 모두 적용한다. 줄글 세 문단을 그림 하나가 대신하면 그림을 쓴다. 설명이 그림보다 길어지면 설명을 지운다.

| 설명하려는 것 | 무엇으로 |
|---|---|
| 요청이 오가는 순서, 어디서 끊기는지 (에이전트 → MCP → guard → 브라우저) | `sequenceDiagram` |
| 구조, 계층, 의존 방향, 모듈 배치 | `flowchart` |
| 상태 전이 (항목 draft → active → discarded, 세션, grant) | `stateDiagram-v2` |
| 테이블과 관계 | `erDiagram` |
| 단계 순서, 작업 의존 | `flowchart LR` |
| 선택지 비교, 결정 근거 | 표 |

- 노드 이름은 한글로 쓰고, 코드 식별자를 짚을 때만 `` ` ``로 같이 단다.
- 그림 하나에 하나만 담는다. 흐름과 구조를 섞지 않는다. 노드가 15개를 넘으면 쪼갠다.
- 문제 지점(평문이 지나가는 곳, 신뢰 경계)은 그림 안에 `Note`, 색, 굵은 화살표로 표시한다.
- 터미널 응답에서는 mermaid 원문 대신 표로 쓴다.
- 최소한: spec은 구조 1장 + 핵심 흐름 1장, plan은 작업 순서 1장, ADR은 결정 전후 구조 1장.
- UI는 headless Chrome 스크린샷으로 라이트·다크를 확인하고, 사람에게 보일 때는 그 경로를 알려 준다.
