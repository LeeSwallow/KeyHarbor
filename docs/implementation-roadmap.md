# KeyHarbor 구현 로드맵

상태: 진행 중. [설계 초안](architecture-proposal.md)과 현재 코드를 연결하기 위한 작업·검증 기준이다. 체크된 항목도 보안 감사나 실제 사이트 호환성의 증거는 아니다.

## 목표 흐름

사용자가 로컬 금고 항목과 작업용 프로필을 선택한다. 에이전트는 해당 작업에 허용된 세션을 요청하고 웹 작업을 수행한다. 로그인이 필요하면 사용자에게 제어를 넘기고, 사용자가 인증을 마친 뒤 에이전트가 같은 작업을 이어간다. 브라우저가 종료돼도 프로필의 유효한 로그인 상태는 재사용한다.

## 현재 증거와 핵심 간격

- SQLite 조건부 갱신과 파일 잠금으로 같은 세션의 중복 실행을 막고, 브라우저 프로필을 별도 경로에 저장한다. 실제 Chrome에서 두 프로필 격리와 감독자 중단 후 수동 복구를 합성 시험했다.
- 브라우저 자식 프로세스 시작 직후 `running` 상태를 기록하지 못하면 감독자가 그 자식의 종료와 회수를 시도한다. SQLite 오류를 강제하는 합성 시험에서 해당 자식 종료를 확인했다. 브라우저가 별도 프로세스를 남겼는지까지 보장하지 않으므로 불확실한 시작 실패는 확인 후 복구해야 한다.
- 감독자는 브라우저가 실행되는 동안 DB 조회 없이 자식 프로세스와 OS 잠금을 유지한다. 세션 테이블을 일시적으로 이용할 수 없게 한 합성 시험에서 잠금이 유지되고 테이블 복구 및 브라우저 종료 후 상태가 기록됐다. 종료 시점에도 DB가 불가능하면 상태가 남으며 수동 복구가 필요하다.
- 로컬 합성 시험에서 24개 CLI 프로세스가 서로 다른 세션을 만들었고, 같은 이름을 요청한 12개 프로세스 중 하나만 성공했다. SQLite 쓰기 잠금을 5초 넘게 유지하면 생성 요청이 오류로 끝나며, 잠금 해제 후 부분 레코드 없이 재시도할 수 있었다. 이는 제한된 경합 시험이며 처리량 목표나 다른 파일시스템의 안정성 증거는 아니다. `cargo test --locked --test sqlite_contention`으로 재현한다.
- 로컬 MCP에서 세션 관리와 선택형 CDP 주소를 제공한다. 단일 세션으로 범위 지정한 MCP 서버는 동일 세션에 하나만 실행되지만, 범위 미지정 서버와 기존 CDP 연결 및 같은 OS 사용자의 셸·DB 접근은 제한하지 못한다. 범위 제한을 설정하지 않으면 모든 세션을 관리할 수 있다. CDP는 해당 브라우저의 전체 권한을 제공하며 사용자 인증 중 이미 연결된 CDP를 철회할 수 없다.
- OpenKeylet 항목 이름은 저장하지만 금고의 존재·대상 사이트를 확인하거나 자동으로 입력하지 않는다. OpenKeylet MCP의 활성 확장 선택은 두 프로필 사이에 바뀔 수 있음을 합성 시험했다.
- 인증 대기는 요청 ID와 실행 generation에 결합해 기록한다. 사용자는 CLI에서 현재 요청 ID와 선택적으로 요청자가 제공한 사이트 출처를 조회하고 그 ID로만 재개할 수 있어 이전 요청의 확인이 새 요청에 적용되지 않는다. 출처와 실제 탭의 일치 여부는 검증하지 않는다. 동일 세션의 동시 인증 요청, 타임아웃, 이전 요청 대체와 재개 후 대기를 시험했다. 이것은 작업을 표시하는 상태이며 로그인 성공이나 실제 사용자 신원을 증명하지 않는다.
- 선택형 로컬 서버는 [설계안](architecture-proposal.md)에만 있고 아직 없다. 실제 Codex·Claude Code 모델 작업에서의 도구 호출은 검증되지 않았다.
- Chrome 디버깅 파이프를 이용한 합성 실험에서는 제어 요청을 차단한 뒤에도 브라우저 안에서 미리 예약된 JavaScript가 실행됐다. 파이프 중개와 연결 종료만으로 인증 중 감시나 요청을 완전히 차단할 수 없다. 실험은 `KEYHARBOR_TEST_CHROME=/path/to/chrome node tests/cdp-pipe-handoff.mjs`로 재현하며, 실제 KeyHarbor의 중개 기능을 시험한 것은 아니다.

## 구현 단계와 완료 조건

1. **세션 수명과 복구**: 프로필 할당, 실행 중·인증 대기·종료·감독자 중단 상태의 의미를 명확히 하고, 중복 할당과 중단된 시작·브라우저 충돌을 재현한다. 실제 프로세스가 살아 있을 때 상태만으로 새 브라우저를 허용하지 않는다. 프로필과 SQLite는 실패 시 보존한다.
2. **실제 사용자 인계**: 에이전트는 인증 대기를 요청하고, 사용자는 대상 계정과 사이트를 확인해 인증한 뒤 재개한다. 에이전트가 대기할 수 있어야 하며 타임아웃·취소·종료·감독자 중단을 다룬다. CLI 재개는 같은 OS 사용자에게 셸 접근이 있는 환경의 보안 경계가 아니라고 명시한다. 인증 성공 판정은 별도이며 자동으로 추정하지 않는다.
3. **작업별 권한과 연결 수명**: 세션을 어떤 클라이언트가 소유하는지 명시하고, 다른 클라이언트의 조회·제어를 차단하는 실제 검증 경계를 설계한다. 인증 인계 시 기존 제어 연결을 끊고 재발급할 수 있는지 검증한다. 원시 CDP 포트를 외부에 직접 공개하는 현재 방식은 이를 보장하지 않으므로, 중개 또는 프로세스 격리 등 대안을 비교·실험한다. 같은 OS 사용자 프로세스나 브라우저 자체가 공격자인 경우의 한계를 분리해 기술한다.
4. **금고 연동**: 금고 항목과 사이트·프로필·탭·프레임의 연결이 실제 입력 직전 검증되는 경로를 먼저 찾는다. OpenKeylet의 현재 활성 확장 기반 자동 입력은 사용하지 않는다. 사용자가 직접 확장 팝업에서 확인하는 경로를 일반 Chrome에서도 시험하고, 자동 입력은 대상 지정과 오용·경합 테스트를 통과한 경우에만 추가한다. 평문 비밀번호, OTP, 쿠키를 KeyHarbor의 MCP/DB/로그로 전달하지 않는다.
5. **통합과 배포**: Codex·Claude Code에서 별도 테스트 계정과 임시 설정으로 등록·도구 발견·실제 호출을 확인한다. 로컬 실행의 장애와 진단을 설명하고, 선택형 로컬 서버는 인증·권한·프로세스 수명 및 기존 CLI와의 경쟁이 해결된 뒤 제공한다. 원격 서버는 별도 신뢰 모델로 취급한다.
6. **보안과 운영**: 프로필·DB·금고·디버깅 엔드포인트의 저장 위치와 암호화 적용 범위를 분리한다. 접근 권한, 백업·삭제·키 유실, 마이그레이션, 로그 보존과 유출 검사를 명세한다. 브라우저 프로필 전체가 암호화됐다고 가정하지 않는다. 테스트 계정과 합성 비밀로 부정 경로를 확인하고, 실제 서비스 호환성과 보안 검토 범위를 구별한다.

## 현재 구현 판단

현재 상태는 로컬 프로토타입이다. 기존 계정에 대한 무인 비밀번호 입력, 공격자에 대한 격리, 인증 중 CDP 접근 회수, OS 재부팅 후 자동 복구는 구현·검증되지 않았다. 완료 판단은 위 단계의 동작과 실패 경로에 대한 증거를 확보한 뒤 수행한다.

## 제어 연결 회수 설계 제약

실행 중인 브라우저에 원시 CDP 포트를 열지 않고 감독자가 디버깅 파이프를 소유하면, 중개 경로에서 새 명령과 연결을 차단할 수 있다. 제품에 적용하려면 세션 실행 generation에 묶인 접근 권한, 인계 시작 시 신규 요청 차단, 기존 연결 종료 및 처리 중 명령의 완료·실패 확인, 명시적인 차단 완료 응답, 재개 시 새 권한 발급과 감독자 장애 처리가 모두 필요하다. 클라이언트와 감독자의 연결을 어떤 OS 권한으로 인증할지도 별도로 결정해야 한다.

그러나 차단 전에 실행한 페이지 스크립트, 확장 프로그램, 서비스 워커 또는 이미 전송한 요청은 연결 종료로 되돌릴 수 없다. 따라서 중개만으로 비공개 인증을 보장해서는 안 된다. 비공개 인증을 요구하는 흐름은 제어되지 않은 별도 브라우저 실행을 사용하고, 기존 프로필의 지속 상태와 사이트의 로그인 정책을 고려해 종료·재시작해야 한다. 프로필에는 쿠키와 기타 민감한 브라우저 데이터가 남을 수 있으며, 브라우저 재시작이 모든 잔존 코드나 인증 위험을 제거한다는 뜻은 아니다.
