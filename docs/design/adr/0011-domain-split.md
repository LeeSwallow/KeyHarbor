# ADR-0011. 세션 · 자격 증명 · 결제 · 개인정보의 네 도메인으로 나눈다

| 항목 | 값 |
|---|---|
| 상태 | Proposed |
| 날짜 | 2026-10-28 |
| 관련 요구 | R-24, R-25 |

## 맥락

관리 대상이 세션, `.env` 변수, 그리고 비밀번호·카드번호를 포함한 자동완성 가능한 개인 정보 전반으로 넓어졌다(R-24). 사용자는 "세션·아이디·비밀번호 같은 기본 정보, 결제 정보, 사용자 개인정보 정도로 분리"하자고 제안했다(R-25). 이 정보들은 유출 피해, 쓰는 곳, origin 바인딩 기본값, 마스킹 특성이 서로 다르다. Chrome 자동완성 설정도 *비밀번호 / 결제 수단 / 주소 및 기타*로 나눈다.

## 결정

1. **세션** 도메인(금고 밖): 브라우저 세션, 인계, 사이트별 로그인 상태.
2. **자격 증명** 도메인: `login`(아이디·비밀번호), `secret`(API 키), `env`(.env 변수 묶음).
3. **결제** 도메인: `card`.
4. **개인정보** 도메인: `identity`, `address`.

정책과 사용 기록은 도메인을 가로지르는 지원 도메인이다. 금고의 세 도메인은 각각 **도메인 키(DK)**로 암호화하고, 금고 키(VK)는 DK를 감싸는 데만 쓴다. 정책 규칙은 도메인 전체를 target으로 삼을 수 있다(`payment:*`). 코드에서는 `kh-domain`의 모듈이 도메인 하나씩에 대응하고, 도메인 사이 참조는 ID로만 한다.

`env`를 자격 증명에 넣은 이유: `.env` 값의 대부분은 서비스 인증용(API 키, DB 접속 정보)이기 때문이다. [설계자 판단]

## 결과

- ADR-0003의 "단일 금고 키로 필드를 직접 암호화" 결정을 **도메인 키 계층으로 대체**한다. VK 교체는 DK 세 개만 다시 감싸면 된다.
- 관리 앱 화면, 정책, 키 교체, 이후의 인증 선택지가 모두 도메인 단위로 정리된다.
- 키 계층이 한 단계 늘어 구현과 테스트 대상이 늘어난다.
