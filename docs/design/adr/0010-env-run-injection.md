# ADR-0010. `.env` 변수는 `keyharbor run`으로 자식 프로세스에만 주입한다

| 항목 | 값 |
|---|---|
| 상태 | Proposed |
| 날짜 | 2026-10-28 |
| 관련 요구 | R-24 |

## 맥락

사용자는 `.env`로 쓰이는 환경 변수도 KeyHarbor에서 관리하길 원한다(R-24). 브라우저 입력과 달리 환경 변수는 프로세스 안에서 평문으로 존재한다. Bitwarden Agent Access는 승인 후 값을 에이전트 프로세스의 환경 변수로 넣는데, 그러면 에이전트가 `echo $KEY`로 값을 볼 수 있어 P4에 어긋난다. 1Password CLI의 `op run`은 자식 프로세스에만 주입하고 그 출력에서 값을 가린다.

## 결정

`env` 항목 종류를 두고, `keyharbor run --env <항목> -- <명령>`과 `--env-file <placeholder 템플릿>`으로 **자식 프로세스에만** 변수를 주입한다. 자식의 stdout·stderr는 금고 전체 값으로 만든 마스커를 거쳐 에이전트에게 돌아간다. 정책으로 항목별로 허용할 에이전트를 정한다. 평문 `.env`는 `vault import-env`로 가져올 수 있다.

## 결과

- 에이전트 문맥과 출력에는 값이 나타나지 않는다.
- 자식 프로세스는 평문을 가지므로, 값을 파일이나 네트워크로 내보내는 것은 막지 못한다(T13). 이 한계를 README와 관리 앱에 표시한다.
- `.env.keyharbor` 템플릿은 비밀이 없으므로 저장소에 커밋할 수 있다.
