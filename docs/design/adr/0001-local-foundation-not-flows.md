# ADR-0001. 로컬 기반 도구로 정의하고 흐름은 제공하지 않는다

| 항목 | 값 |
|---|---|
| 상태 | Proposed |
| 날짜 | 2026-10-28 |
| 관련 요구 | R-13, R-19 |

## 맥락

처음 요구(R-01, R-03, R-04)는 KeyHarbor가 로그인·회원가입·약관 동의·인증까지 직접 수행하는 것이었다. 이후 사용자가 "흐름 관리까지 하는 게 아니라 그걸 하기 위한 기반을 제공하는 것"(R-13)이라고 재정의했고, "개인이 에이전트를 권한 정책에 따라 중단 없이 쓰게 하는 무료 오픈소스 로컬 도구"(R-19)로 제품을 정의했다.

## 결정

KeyHarbor는 세션·금고·치환·마스킹·정책·상태·기록·관리 앱이라는 **기반**만 제공한다. 로그인·가입·CAPTCHA 대응·인증 코드 수신은 에이전트(또는 그 위의 skill)가 이 기반을 조합해 수행한다. 필수 외부 서비스는 없다.

## 결과

- 범위가 줄고 경계가 분명해진다. 사이트별 휴리스틱(로그인 화면 인식 등)을 KeyHarbor가 유지보수하지 않는다.
- 에이전트 쪽에 흐름 구현 부담이 남는다. 6단계 플러그인 skill에서 사용 예시를 제공해 덜어 준다.
